- (decision) MVP scope = Phase 1 only from source docs: permissions/domains + supported-body management + contact management + public registration form. Phases 2-4 (groups, messaging, incoming correspondence, personal area) explicitly out of scope.
- (decision) Working mode: Fast Path chosen by user. Risk tier: 'Mixed - public-facing surface' chosen (not pure internal) because the anonymous public registration form is exposed to the internet without auth.
- (decision) 'Supported body' (גוף נתמך) will be built as a full standalone entity/CRUD within the MVP itself, not imported from an existing external registry. This resolves source doc's open question about which source verifies the ח"פ number during public registration matching (FR-14/16) - it matches against our own internal registry.
- (decision) 'Domain' (תחום) is a closed list managed only by super-admin (not user-creatable elsewhere).
- (assumption) Internal user authentication mechanism (SSO vs new login system) left explicitly open per user request; deferred to architecture phase.
- (assumption) מרכבה sync (NFR-1/CM-2) explicitly deferred out of MVP per user request; MVP assumes manual/one-time import only.
- (assumption) Supported body assumed to belong to a single responsible domain for MVP permission purposes; multi-domain grouping deferred to Phase 2 (GR-3-GR-5).
